# Скиллы проекта

Подключаются автоматически в любой сессии по этому репозиторию — лежат в git,
поэтому переживают пересоздание контейнера.

## Как перенести в другой чат

Ключевой момент: **домашний каталог сессии живёт до конца сессии, репозиторий
— всегда.** В Claude Code на вебе контейнер пересоздаётся, и всё, что положено
в `~/.claude/skills/`, исчезает вместе с ним. Поэтому скиллы лежат в проекте, а
не в домашнем каталоге.

Отсюда три случая:

**Тот же репозиторий, другой чат.** Ничего делать не нужно — скиллы уже здесь
и подхватятся сами.

**Другой репозиторий.** Скопировать нужные папки в его `.claude/skills/` и
закоммитить. Одной командой в сессии по тому репозиторию:

```bash
git clone --depth 1 https://github.com/dkaratsapov-web/landing /tmp/src
mkdir -p .claude/skills
cp -r /tmp/src/.claude/skills/design-taste-frontend \
      /tmp/src/.claude/skills/high-end-visual-design \
      /tmp/src/.claude/skills/redesign-existing-projects \
      .claude/skills/
rm -rf /tmp/src
git add .claude/skills && git commit -m "skills: дизайнерский набор" && git push
```

Если репозиторий приватный, у той сессии должен быть к нему доступ — иначе
проще перенести файлы руками, они текстовые.

**Claude Code на своей машине.** Там домашний каталог никуда не девается:
положить папки в `~/.claude/skills/`, и они будут во всех проектах сразу.

Скилл — это просто каталог с `SKILL.md` (и, если нужно, `references/`).
Никакой установки, кроме копирования файлов, не существует.

## Сколько ставить

Чем больше скиллов, тем хуже они срабатывают: описания начинают пересекаться,
и подхватывается не тот. Брать по задаче, а не «все, что нашлись».

### Дизайн и фронтенд

| Скилл | Откуда | Зачем здесь |
|---|---|---|
| `design-taste-frontend` | Leonxlnx/taste-skill | Главный. Определяет направление по задаче, ставит степень асимметрии, движения и плотности. Большой список запретов на типовые ИИ-решения — в том числе на градиент из бирюзы в фиолетовый |
| `high-end-visual-design` | источник не записан | «Дорогой» вид: вложенные рамки, кнопка-в-кнопке, крупные отступы, кастомные кривые анимаций вместо `ease-in-out` |

стилевые, включаются только под соответствующую задачу.

## Что стоило бы добавить

Все дизайнерские скиллы отвечают на вопрос «как сделать красиво». Ни один не
отвечает на «как убедиться, что не сломал». Проверки этого проекта —
горизонтальная прокрутка, мёртвые scroll-анимации, тёмные полосы на стыках
блоков, обрезанный многоточием текст, зоны нажатия меньше пальца — живут в
`project/check.mjs` и работают только здесь. Их стоит вынести в скилл, чтобы
«сделай красиво» и «докажи, что цело» ходили парой.

## Чего здесь нет

`ui-ux-pro-max` (nextlevelbuilder) собрать не удалось: он тянет каталог с
данными, а через прокси этого окружения недоступны ни архив репозитория, ни
GitHub API — перечислить имена файлов нечем. Ставится локально своим CLI.
