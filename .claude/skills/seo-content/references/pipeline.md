# Как публикуется статья

## Фронтматтер

Файл кладётся в `project/blog/<slug>.md`. Слаг — латиницей, через дефис, он же
становится адресом: `/blog/<slug>/`.

```yaml
---
title: Заголовок статьи — с целевым запросом
description: Два-три предложения. Попадает в выдачу под заголовком.
date: 2026-08-15
cover: /assets/blog/<группа>-cover.jpg
tags: [Яндекс Директ, Бюджет, Для новичков]
service: /kontekstnaya-reklama/
---
```

Что ломается без каждого поля:

| Поле | Обязательно | Без него |
| --- | --- | --- |
| `title` | да | сборка падает |
| `description` | да | сборка падает; это же текст под ссылкой в выдаче |
| `date` | да | сборка падает; ломается сортировка ленты и `lastmod` в карте сайта |
| `cover` | нет | статья без превью в ленте и без картинки при репосте |
| `tags` | нет | нет плашек над заголовком |
| `service` | нет | нет нижнего блока со ссылкой на услугу — трафик никуда не ведёт |
| `updated` | нет | ставится при существенной правке, не при опечатке |
| `draft: true` | нет | исключает статью из сборки |

`lastmod` в карте сайта берётся из `updated` или `date`, а не из даты коммита:
правка опечатки не должна выглядеть для поисковика обновлением материала.

## Картинки

Спеки — в `project/illustrations.mjs`, для внешних площадок в
`external-content/illustrations-external.mjs`. Имя файла складывается как
`<группа>-<имя>.jpg`, группа обычно совпадает со слагом статьи.

Пять типов карточек:

- `cover` — обложка: `eyebrow`, `title` (перенос через `\n`), `withPhoto`
- `stats` — до четырёх крупных цифр: `[[значение, подпись], …]`
- `steps` — нумерованная последовательность
- `compare` — две колонки, правая подсвечена как правильная
- `checklist` — тезисы; `negative: true` рисует крестики
- `quote` — крупный тезис плюс необязательный комментарий

Размеры: `cover-site` 1200×630, `cover-dzen` 1600×900, `inline` 1200×750.

Запуск:

```bash
node project/gen-illustrations.mjs                    # всё
node project/gen-illustrations.mjs <группа>           # одна статья

ILL_SPECS=../external-content/illustrations-external.mjs \
ILL_OUT=external-content/images \
node project/gen-illustrations.mjs                    # Дзен и VC
```

Высота подбирается сама: генератор ищет подпись на готовой картинке и
перерисовывает выше, если она не поместилась. Если не влезает и в максимум —
падает с ошибкой, а не выпускает обрезанную карточку. Значит, текст в спеке
надо сократить.

Обложки статей делаются **без портрета** (`withPhoto: false`): в ленте десяток
карточек с одним и тем же фото читается как сбой вёрстки.

## Куда ставить картинки в тексте

Туда, где содержание само просится в схему: перечисление шагов, сравнение
вариантов, набор цифр, список ошибок. Связный рассуждающий текст картинкой не
заменяется — аргументацию всё равно читают словами.

Две-четыре на статью. У каждой осмысленный `alt`: он и для поиска по
картинкам, и для тех, у кого изображения не загрузились.

## Проверки перед деплоем

```bash
npm run build
```

Смотри на строки `Блог: N статей`, `Generated sitemap.xml`, `Вычищено
исходников`. Затем:

**Битые ссылки и картинки.** Обход всех html в `dist` с проверкой каждого
`href` и `src`. Ссылка на несуществующую статью сборку не ломает — её ловит
только эта проверка.

**Утечка исходников.** В `dist` не должно быть `.mjs`, `.md`, `.jsx` и
`seo.config.json`. `npm run build` начинается с `cp -r project dist`, поэтому
туда попадает всё дерево; вычищает рекурсивная зачистка в конце сборки.

**Расхождения с прайсом.** Если в статье есть цифры из `references/facts.md` —
сверь их со страницей цен. Читатель кликает со статьи на прайс.

## Деплой

```bash
git add -A && git commit
git checkout main && git merge --ff-only claude/<ветка>
git push -u origin main
```

Дальше дождаться, пока GitHub Pages опубликует, и проверить по ветке
`gh-pages` — это ровно то, что отдаёт хостинг:

```
https://raw.githubusercontent.com/dkaratsapov-web/landing/gh-pages/<путь>
```

Проверять именно так, а не по домену: прокси песочницы на сайт не пускает.

Смотреть: `canonical` ведёт на `karatsapov.ru`, статья на месте, карта сайта
содержит новый адрес.

## После публикации

Отправить адрес на переобход в Яндекс.Вебмастере. Иначе статья попадёт в
индекс за недели вместо дней. Квота дневная — повторные отправки одного адреса
её жгут без пользы.
