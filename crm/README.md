# Сервис работы с базами компаний

Импорт справочников, проверка сайтов, приоритет и повод для разговора по
каждой компании, мини-CRM поверх всего этого.

Сервис живёт **отдельно от сайта**. Это не прихоть: деплой сайта идёт
`rsync --delete` в `/var/www/landing/`, и всё, что окажется в этом каталоге
мимо сборки, будет стёрто следующим пушем. Поэтому код — в `/opt/crm`,
база — в `/var/lib/crm`.

## Зависимостей нет

Ни одной. Только то, что есть в Node из коробки, — поэтому на сервере не нужен
`npm install`, нечему протухать и нечего обновлять по уязвимостям.
Разворачивание сводится к копированию каталога.

Нужен Node 18 или новее.

## Быстрый старт на своей машине

```bash
CRM_PASSWORD=любой-пароль node server.mjs
# открыть http://127.0.0.1:8787
```

Переменные: `CRM_PORT` (8787), `CRM_HOST` (127.0.0.1),
`CRM_DATA` (`./data/base.ndjson`), `CRM_SECRET` (если не задан — случайный,
и тогда перезапуск разлогинивает).

## Вход

Два способа, можно включить оба или любой один. Если не настроен ни один,
сервис не стартует.

**По паролю** — `CRM_PASSWORD`. Годится для локальной работы и как запасной
вход, если с Яндексом что-то не так.

**Через Яндекс ID** — вход яндекс-почтой.

```
CRM_YANDEX_CLIENT_ID=...
CRM_YANDEX_CLIENT_SECRET=...
CRM_BASE_URL=https://crm.karatsapov.ru
CRM_ALLOWED_EMAILS=вы@yandex.ru,коллега@yandex.ru
```

Настройка приложения:

1. <https://oauth.yandex.ru/client/new>, платформа — «Веб-сервисы»
2. Redirect URI: `https://crm.karatsapov.ru/auth/yandex/callback` — ровно
   такой же, как `CRM_BASE_URL` плюс этот путь, иначе Яндекс откажет
3. Доступы: «Доступ к адресу электронной почты» и «Доступ к логину, имени
   и фамилии»
4. ID и пароль приложения — в `/etc/crm.env`

**Про `CRM_ALLOWED_EMAILS` — это и есть замок.** OAuth отвечает только на
вопрос «человек действительно владеет этим яндекс-аккаунтом», и успешно
ответит кому угодно: яндекс-почта есть у ста миллионов человек. Пускает
внутрь список адресов, а Яндекс лишь подтверждает личность. Поэтому пустой
список означает «не пускать никого», и сервис с настроенным Яндексом, но
пустым списком не стартует.

Права сверяются при каждом запросе, а не один раз при входе: достаточно
убрать адрес из списка и перезапустить сервис, чтобы человек потерял доступ
немедленно, не дожидаясь, пока истечёт его кука.

## Что умеет

**Импорт.** CSV и XLSX. Колонки распознаются по шапке — её необязательно
приводить к какому-то виду, достаточно, чтобы заголовки назывались по-русски
понятными словами. Шапка ищется в первых тридцати строках, поэтому пустые
строки и заголовок отчёта сверху не мешают.

Дубли сливаются, а не задваиваются: ключ — домен, а если его нет, название
плюс город. Слияние не затирает проставленные руками статус и заметку, а
только дописывает недостающие телефоны и почты. Перед каждым импортом
делается копия базы в `data/backups/`.

Старый `.xls` (Excel до 2007) не поддерживается намеренно: это бинарный формат
с собственной файловой системой внутри, и ради него пришлось бы тащить
зависимость. Пересохранить в `.xlsx` — два клика.

**Проверка.** По каждой компании с сайтом:

| Что смотрим | Зачем |
| --- | --- |
| DNS и HTTP | жив ли домен вообще |
| редиректы | ловим переезд на новый домен — контакт в справочнике устарел |
| заглушки и парковки | домен отвечает, но бизнеса за ним нет |
| счётчики Метрики, GA, Mail.ru, VK | **нет счётчика — рекламу не ведут** |
| движок сайта | Tilda, uCoz, UMI и прочие — визитка, а не инструмент |
| адаптив, форма заявки, онлайн-чат | поводы для разговора |
| год в копирайте | сайтом давно не занимались |

Идёт в фоне, примерно 4–6 компаний в секунду, окно можно закрыть. Один запрос
на домен, честный User-Agent, таймаут 10 секунд, больше 256 КБ страницы не
читаем.

**Приоритет.** Правила — в `score.mjs`, одним файлом и словами. Самый тяжёлый
признак — отсутствие счётчиков: это и значит, что компания не ведёт рекламу.
Отдельно поднимаются ниши, где уже есть кейс по Твери.

**Работа с базой.** Фильтры по статусу, состоянию сайта, предлагаемой услуге,
нише, городу и наличию контактов. Карточка с историей касаний. Экспорт в CSV
с BOM — русский Excel откроет без кракозябр.

## Разворачивание на VPS

```bash
# 1. код
rsync -av --exclude data --exclude node_modules crm/ root@СЕРВЕР:/opt/crm/

# 2. каталог для базы
ssh root@СЕРВЕР 'mkdir -p /var/lib/crm && chown www-data:www-data /var/lib/crm'

# 3. пароль и путь к базе
ssh root@СЕРВЕР 'cat > /etc/crm.env <<EOF
CRM_PASSWORD=длинный-пароль
CRM_DATA=/var/lib/crm/base.ndjson
EOF
chmod 600 /etc/crm.env'

# 4. сервис
scp crm/deploy/crm.service root@СЕРВЕР:/etc/systemd/system/
ssh root@СЕРВЕР 'systemctl daemon-reload && systemctl enable --now crm'

# 5. Nginx и сертификат — см. deploy/nginx.conf.example
```

Бэкап — это копирование одного файла:

```bash
scp root@СЕРВЕР:/var/lib/crm/base.ndjson ./backup-$(date +%F).ndjson
```

## Приём заявок с сайта

Эндпоинт `POST /api/lead` — единственный метод без входа: его дёргает
посетитель сайта, а не владелец. Своя защита внутри: проверка источника,
ограничение частоты (8 обращений с адреса за 10 минут), honeypot и запись
на диск **до** отправки, чтобы недоступность мессенджера означала «заявка
полежит в файле», а не «заявка потеряна». Это же и есть первичная запись
персональных данных на российском сервере по 152-ФЗ.

```
LEAD_MAX_TOKEN=...        # токен бота из business.max.ru
LEAD_MAX_USER_ID=...      # кому слать
LEAD_TG_TOKEN=            # необязательно, второй канал
LEAD_TG_CHAT=
LEAD_FILE=/var/lib/crm/leads.ndjson
LEAD_ORIGINS=https://karatsapov.ru
```

На сайте секретов нет: `project/lead-config.js` знает только адрес
`/api/lead`, а Nginx проксирует его на сервис — см.
`deploy/nginx-lead.conf.example`. Если эндпоинт не ответил за восемь секунд
или вернул ошибку, форма открывает WhatsApp с готовым текстом.

### Что нужно сделать в MAX

1. Завести **верифицированный профиль** организации, ИП или самозанятого на
   платформе MAX для партнёров. Физическому лицу без такого статуса бота не
   создать — это ограничение самого MAX, обойти его нельзя.
2. Создать бота, заполнить карточку и отправить на модерацию: **до 48 часов
   по рабочим дням**. Пока не пройдена — доставки не будет.
3. Токен скопировать в `/etc/crm.env`. В чат и в репозиторий он не попадает
   никогда.
4. Узнать свой `user_id`. Отдельного метода «верни мой идентификатор» в API
   нет: он приходит только внутри событий. Поэтому — написать боту `/start`
   в MAX, а потом запустить помощник, он всё разберёт сам:

   ```bash
   LEAD_MAX_TOKEN=... node tools/max-whoami.mjs
   ```

   Помощник проверит токен, покажет бота и выведет готовую строку для
   `/etc/crm.env`. Он только читает: ничего не отправляет и не меняет.

### Подключение по шагам

```bash
# 1. код на сервер
rsync -av --exclude data --exclude node_modules crm/ root@СЕРВЕР:/opt/crm/

# 2. сертификат Минцифры (без него запрос к MAX падает на TLS)
#    скачать с gosuslugi.ru, положить и обновить хранилище:
update-ca-certificates

# 3. настройки
cat >> /etc/crm.env <<'ENV'
LEAD_MAX_TOKEN=<токен из business.max.ru>
LEAD_MAX_USER_ID=<из tools/max-whoami.mjs>
LEAD_FILE=/var/lib/crm/leads.ndjson
LEAD_ORIGINS=https://karatsapov.ru
NODE_EXTRA_CA_CERTS=/usr/local/share/ca-certificates/russian_trusted_root_ca.crt
ENV
chmod 600 /etc/crm.env

# 4. перезапуск и проверка
systemctl restart crm && journalctl -u crm -n 20 --no-pager

# 5. Nginx: добавить блок из deploy/nginx-lead.conf.example
nginx -t && systemctl reload nginx

# 6. контрольная заявка — должна прийти в MAX
curl -s -X POST https://karatsapov.ru/api/lead \
  -H 'content-type: application/json' \
  -H 'origin: https://karatsapov.ru' \
  -d '{"name":"Проверка","phone":"+7 996 347 00 65","source":"ручная проверка"}'
```

Ожидаемый ответ — `{"ok":true,"delivered":"max"}`. Если `"delivered":"stored"`,
заявка принята и лежит в файле, но до MAX не дошла: смотреть
`journalctl -u crm` — там будет причина.

### Сертификат Минцифры

`platform-api2.max.ru` работает с сертификатом российского удостоверяющего
центра, которого в стандартном наборе Node нет. Без него запрос падает на
проверке TLS ещё до ответа. Корневой сертификат ставится в систему, а Node
указывается на него:

```
NODE_EXTRA_CA_CERTS=/usr/local/share/ca-certificates/russian_trusted_root_ca.crt
```

Переменную добавить в `/etc/crm.env`. Если доставки нет, а в журнале
`certificate` или `self-signed` — причина эта.

### Ограничения MAX

30 запросов в секунду на сервис и не более двух сообщений в секунду в один
диалог. Для формы заявок это недостижимо, но если когда-нибудь добавится
рассылка — помнить.

## Тесты

```bash
node test-check.mjs    # проверка сайтов
node test-auth.mjs     # вход через Яндекс
node test-lead.mjs     # приём заявок и доставка в MAX
```

Поднимает поддельные сайты на `127.0.0.1` и проверяет на них все случаи, ради
которых чекер и писался: сайт со счётчиком и без, конструктор, парковка,
переезд, 404, страница в windows-1251. Внешнюю сеть тесты не трогают.

На время прогона в `/etc/hosts` добавляются имена `*.test` — чекер ходит по
имени домена, подменить его адресом нельзя. После прогона файл
восстанавливается.

`test-auth.mjs` поднимает поддельный Яндекс и гоняет через него весь сценарий
входа: подмену `state`, повторное использование кода, чужой аккаунт, аккаунт
без почты, отказ пользователя, подделку куки. Настоящий `oauth.yandex.ru`
тесты не трогают.

## Про персональные данные

Мобильный телефон предпринимателя и ФИО директора — персональные данные.
Если вы их храните, вы оператор ПДн: нужно уведомление в Роскомнадзор
(подаётся онлайн, бесплатно) и хранение на российском сервере.

`.gitignore` закрывает `data/` и любые выгрузки. Это не перестраховка: один
коммит с базой делает её общедоступной навсегда — история остаётся в форках
и в кэше GitHub.

Холодная рассылка по такой базе подпадает под ст. 18 закона «О рекламе».
Безопасный заход — не реклама, а конкретный разбор: «посмотрел ваш сайт, на
нём нет счётчика, вы не видите, откуда приходят клиенты». Ровно это и
подставляется в поле «повод для разговора».
