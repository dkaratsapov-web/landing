## 0. СРОЧНО, вне кода: отозвать токен Telegram-бота


Токен бота и id чата какое-то время отдавались публично по адресу
`https://karatsapov.ru/lead-config.js`. Из репозитория я их убрал, но
**удаление из кода не отзывает токен**. Кто успел его забрать, до сих пор
может читать все заявки через `getUpdates`.

Что сделать (руками, в Телеграме):
1. @BotFather → `/mybots` → выбрать бота → API Token → **Revoke current token**.
2. Новый токен **не класть в репозиторий**. Клиентский код в браузере не может
   хранить секреты в принципе — что угодно, попавшее в `lead-config.js`, видно
   любому посетителю через «Просмотр кода».
3. Правильное решение — маленький прокси на том же сервере: форма шлёт заявку
   на свой же домен, а токен лежит в переменной окружения на сервере и наружу
   не выходит. Файл `project/lead-config.js` сейчас с пустыми значениями и
   комментарием об этом.

Пока токен не отозван — считать канал заявок скомпрометированным.

## 1a. Цели в Яндекс.Метрике

Счётчик стоит, но целей толком нет — значит нельзя сказать, какая реклама
приносит заявки, а какая жжёт бюджет. Без этого и сквозная аналитика не
соберётся: ей нечего связывать с рекламой.

Что нужно завести:

- **Отправка формы** — основная цель. Форма на сайте одна (модальное окно
  заявки), отправляется через JS, поэтому цель составная: событие
  `reachGoal('lead_form')` в момент успешной отправки, а не по клику на
  кнопку. По клику считать нельзя — часть отправок падает.
- **Клик по мессенджерам** — Telegram, MAX, телефон. Отдельные цели, потому
  что это разные по качеству обращения.
- **Заказ бесплатного аудита** — отдельная форма на `/audit-reklamy/` и на
  главной. Считать отдельно от общей заявки: у неё другая мотивация и другая
  конверсия в деньги.
- **Открытие квиза и его прохождение до конца** — две цели, чтобы видеть,
  на каком шаге отваливаются.
- **Дочитывание страницы услуги** — цель по глубине прокрутки (75%). Нужна
  не сама по себе, а как признак заинтересованного трафика: по ней видно,
  приводит ли кампания людей, которым тема интересна.

Отдельно — разметить рекламные переходы UTM-метками и проверить, что цели
действительно срабатывают (в Метрике есть режим проверки).

Файлы: `project/audit-contacts-quiz.jsx` (формы и квиз),
`project/lead-config.js`, счётчик — в `project/layout.mjs`.

## 8. Хвосты по серверу и индексации

Сайт переехал на VPS `194.67.101.183`, сертификат до 14.11.2026,
автопродление проверено. Осталось:

- **HSTS** — включить через несколько спокойных дней, не раньше. Заголовок
  говорит браузеру «ходи сюда только по https» и запоминается надолго; если
  включить до того, как всё устоялось, откатить будет тяжело.
- **GitHub Pages** — отключить workflow примерно через две недели, когда
  станет понятно, что VPS держит нагрузку. Пока это запасной вариант.
- **DNS** — удалить запись `TXT _github-pages-challenge`, она больше не нужна.
- **Яндекс.Вебмастер** — на старой http-записи: Индексирование → Переезд сайта,
  указать https основным зеркалом. Затем отправить на переобход список из
  31 адреса.

## Как проверять работу

```
npm run build        # сборка (не запускать build.mjs напрямую — пишет не туда)
node project/check.mjs   # проверки: стыки блоков, мёртвые анимации, тап-таргеты
```

`check.mjs` умеет ловить две вещи, которые я сам несколько раз ломал:

- **мёртвые прокруточные анимации.** `overflow: hidden` создаёт контейнер
  прокрутки, а `view()` привязывается к ближайшему такому контейнеру. Если он
  не прокручивается, прогресс анимации застревает на нуле, и элемент с
  `fill: both` остаётся навсегда прозрачным. Лечится заменой на
  `overflow: clip` — обрезает так же, но контейнера прокрутки не создаёт.
  Именно так пропадали орбита на `/about/` и кнопка «Назначить встречу».
- **тёмные полосы на стыках** — пиксельным замером тона, а не на глаз.
